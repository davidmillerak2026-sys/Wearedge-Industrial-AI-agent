# 赛事要求与 Wearedge 工业智能体优化方向

更新时间：2026-06-04

## 1. 赛事硬信息

赛事名称：第十一届“创客中国”工业智能体中小企业创新创业大赛。

适配我们当前方向的赛题：西门子 Xcelerator 工业智能体赛题，围绕西门子数字化工业真实产线环境，聚焦智能产线协同、预测性维护、质量闭环控制三个场景。

五个智能体赛题方向：质量管控智能体、能源管理智能体、设备运维智能体、生产制造-柔性生产智能体的协同决策、基于工易魔方开发的智能体。官方细则要求从五个方向中选取不少于三个智能体方向，探索联合解决方案。

赛程节奏：报名 2026 年 5 月至 7 月，初赛 7 月，复赛 8 月，决赛和颁奖 9 月。官网时间轴显示报名截止为 2026-07-10，初赛评审 2026-07-20，复赛评审 2026-08-10，线下决赛拟 2026-09-04，颁奖拟 2026-09-05。

初赛商业计划书至少要覆盖：项目背景、智能体开发思路及总体框架、技术基础或能力、详细方案（功能划分、算法设计、模型选择、工作流定义等）、成果截图及优势、开发投入、预期效果及收益、团队介绍、企业情况、知识产权证明或承诺。

评审维度：创新性 30%，技术水平 30%，应用前景 20%，团队能力 10%，可行性 10%。

西门子细则中的阶段指标：

- 初赛：完成单智能体核心功能开发，故障预测准确率不低于 85%，或调度优化效率提升不低于 20%；提交技术方案文档与算法原型代码，或提交可执行的工易魔方工作流；通过离线数据集验证。
- 决赛：不少于三个智能体赛题方向形成联合解决方案；在西门子 Xcelerator 智能体开发平台完成端到端验证，或在工易魔方软件工程环境中实现工作流执行验证；系统响应延迟不高于 500ms，决策准确率不低于 90%；人机协同界面支持自然语言交互与决策过程可视化。

关键专项指标：

- 质量管控：检测准确率和良品率相对传统方案提升 5%；加分项是 AI 大模型带来过去未实现的 1-2 个质量能力，或异常响应、系统化监测、预防能力效率提升 10%。
- 能源管理：能耗预测准确度目标不低于 95%；AI 智能节能率目标不低于 10%。
- 设备运维：故障预测 F1 Score 大于 85%，故障预警提前时间大于 24 小时；根因定位 Top 3 命中率大于 90%。
- 柔性生产：看按需切换工艺的方法、应对变更的技术工作方式、新型谱产品生产能力、订单交期/成本等客户价值、创新性；判别标准包括敏捷度、灵活度、人工依赖程度、组件标准化程度与复用率。
- 工易魔方融合：看与工易魔方的融合协同程度、对现有功能组件的利用率、新开发功能组件的商业价值与复用潜力、与工易魔方生态伙伴的融合程度。

## 2. 工易魔方相关约束

工易魔方定位不是单纯展示工具，而是轻量化 AI 原生数字底座：以 IT 低代码方式对制造过程做标准化、模块化定义与配置，与现有 IT 系统无侵入式互联互通，并对 OT 设备进行调度、控制、反馈。

适用场景包括：制造业数字化转型中的跨领域技术融合降本提效、AI 与具身智能技术落地、柔性生产系统构建。

核心能力包括：IT/OT 低代码工作流工程平台、CREEM 通用信息模型、SPIDR 轻量调度器运行时、3D Visualization 在线/离线仿真、DevKit 与 Market、Dashboard 看板、DataLayer 知识中台集成。

二次开发方式：可创建自定义资源块和自定义功能块。已有 IT 服务、MES、AI 服务或本地算法可以通过 REST API、Python 功能块、输入输出端口、资源绑定参数接入工易魔方。运行结果可写入全局数据表，再通过 ui-builder / Dashboard 展示。

OT 接入方式：资料中明确覆盖 PLC/DCS、机器人、末端执行器、AGV、摄像头、传感器、I/O、CNC、生产机械等，也提到 OPC UA、MQTT、BACnet、S7 等协议能力。

部署方式：可云端 Web 开发，也可本地/边缘部署。实际控制场景通过 SPIDR 蜘蛛执行器连接边缘设备或 IPC，常见运行端口为 3002。

## 3. 推荐参赛主线

建议将 Wearedge 定位为：

**面向柔性可重构产线的多智能体协同决策与自主执行系统**

一句话表达：

Wearedge 将质量、能耗、设备健康与生产换型需求统一进一个可解释、可执行、可回写的工业多智能体闭环，通过工易魔方把 AI 决策转化为可验证的 IT/OT 工作流。

这个方向比“工业问答助手”更贴赛题，因为它同时命中质量管控、能源管理、设备运维、柔性生产协同决策和工易魔方开发五个方向。初赛可以先做一个核心智能体和可执行工作流，决赛再扩展为至少三个智能体联合方案。

## 4. 建议智能体架构

最小可演示架构：

1. 数据接入层：工易魔方读取 MES 订单、设备信号、质量检测结果、能耗数据、维护日志。
2. 证据层：设备知识库、工艺 SOP、故障案例、阈值规则、历史 KPI。
3. 智能体层：
   - 质量智能体：识别缺陷趋势，定位可能工艺参数或设备状态原因。
   - 能源智能体：识别空转、峰值、低效运行，提出节能控制建议。
   - 运维智能体：根据报警、振动/温度/电流、历史故障做 RCA 和工单建议。
   - 柔性生产智能体：根据订单变化、设备状态和质量风险建议工作流调整。
   - 安全闸门智能体：把 AI 建议转成可审批动作，限制直接写入 OT。
4. 执行层：工易魔方功能块执行读变量、写变量、调用 AI 服务、更新数据表、提交工单、更新看板。
5. 展示层：WFC 工作流画布、Dashboard、ui-builder、3D 仿真画面、运行日志。

建议参赛组合：

- 初赛最小组合：设备运维智能体 + 工易魔方工作流。原因是细则给了明确指标，F1 Score、预警提前时间、RCA、工单生成都容易用离线数据集验证。
- 决赛推荐组合：设备运维智能体 + 质量管控智能体 + 柔性生产智能体 + 工易魔方执行底座。能源管理可作为加分模块加入，但不要牺牲前三者闭环质量。
- 高分叙事：用设备异常或质量波动触发柔性生产工作流调整，形成“识别异常 -> 根因定位 -> 决策建议 -> 人工确认 -> 工易魔方执行 -> 数据回写 -> 可视化解释”的完整闭环。

## 5. 工易魔方落地实现建议

创建一个自定义资源块：`Wearedge Agent Service`

资源参数：`agentHost`、`agentPort`、`apiKeyRef`、`plantId`、`lineId`。

创建一组自定义功能块：

- `采集上下文`：从 MES/数据表/OPC UA/S7/传感器聚合当前生产状态。
- `异常判定`：确定性阈值与轻量模型先做快速判断，避免大模型直接判断安全边界。
- `智能体诊断`：调用 Wearedge Agent Service，输出 RCA、置信度、证据、建议动作。
- `协同决策`：在质量、能耗、运维、产能之间做多目标权衡。
- `人工确认`：把高风险动作变成审批项，而非直接控制设备。
- `执行与回写`：经审批后调用工易魔方已有设备/控制功能块。
- `看板更新`：把诊断结果、图片 URL、指标变化写入全局数据表并展示。
- `工单生成`：生成维护任务、备件建议、停机窗口建议。

建议输出指标字段：

- `latency_ms`：服务端智能体响应时间，目标小于 500ms；长链路诊断可异步执行，前台先返回初判和任务号。
- `decision_accuracy`：决策准确率，决赛目标不低于 90%。
- `maintenance_f1`：设备预警 F1 Score，目标大于 85%。
- `warning_lead_time_hours`：故障预警提前时间，目标大于 24 小时。
- `root_cause_top3_hit`：根因 Top 3 命中率，目标大于 90%。
- `quality_improvement_pct`：检测准确率或良品率提升，目标不低于 5%。
- `schedule_efficiency_gain_pct`：调度优化效率提升，初赛目标不低于 20%。

演示工作流建议做成三段：

1. 订单变化触发柔性换型。
2. 换型后出现质量波动和能耗异常。
3. 智能体给出证据链、调整建议、工单和仿真验证，经人工确认后由工易魔方执行。

## 6. 参赛材料应突出什么

创新性：强调“工业智能体不是聊天界面，而是能在 IT/OT 闭环里协同决策的可执行系统”。突出多智能体协同、知识沉淀、可重构工作流、AI 建议到 OT 执行之间的安全闸门。

技术水平：展示模型、算法、工具调用和工易魔方功能块的组合。重点写清楚功能划分、算法设计、模型选择、工作流定义、数据流、审批流、异常处理。

应用前景：选择一个非常具体的场景，例如“多品种小批量产线换型中的质量-能耗-运维协同优化”，用开发效率、换型时间、能耗、停机时间、缺陷率、工单响应时间做收益指标。

团队能力：准备工业场景专家、AI/算法、IT/OT 集成、前端/看板、项目交付五类角色说明。

可行性：不要把所有工业场景都做完。先做一个可跑通的端到端闭环，真实设备不足时用工易魔方 3D 仿真和模拟数据补齐，但保留与真实 SPIDR/IPC/机器人/PLC 接入的接口。

## 7. 优先级路线图

P0：完成商业计划书结构，明确选择西门子 Xcelerator 工业智能体赛题，确定初赛核心智能体、决赛不少于三个智能体方向和可量化指标。

P1：搭建 Wearedge Agent Service 的 REST API，至少支持诊断、决策、工单、看板数据四类接口，并记录 `latency_ms`。

P2：在工易魔方中创建自定义资源块和 Python 功能块，跑通“调用智能体服务 -> 输出 JSON -> 更新数据表 -> Dashboard 展示”，形成可提交的工易魔方工作流。

P3：接入至少一类 OT 或模拟 OT 数据：OPC UA/S7 变量、机器人点位、视觉检测结果、能耗数据任选其一；初赛优先使用离线数据集验证。

P4：加入设备知识库和故障案例，让 RCA 输出带证据、阈值、置信度和残余风险。

P5：做 3D 仿真或看板截图，用于初赛材料中的“智能体成果展示”。

P6：复赛/决赛前补充现场答辩 Demo：异常触发、诊断解释、人工确认、工作流执行、结果回写，并扩展到不少于三个智能体方向。

## 8. 避坑清单

不要做成泛泛的工业 Chatbot。评审会看智能体能否解决实际工业场景问题。

不要只展示模型推理。需要体现工作流定义、设备/系统集成、数据回写和执行闭环。

不要让大模型直接控制 OT 设备。高风险控制要经过规则校验和人工确认。

不要横跨太多行业。赛题一已经足够大，最好选一个制造场景深挖。

不要忽略截图和成果展示。初赛材料明确要求智能体成果截图及说明。
